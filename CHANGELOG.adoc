All notable changes to the Aladdin specification are recorded here.

The specification follows Semantic Versioning. While the series is `0.x`,
breaking changes are possible between minor versions and every one of them is
announced in this file.

== Unreleased

=== Breaking

* Schema identifiers changed from `github.com/.../blob/main/...` to versioned
  raw URLs of the form
  `https://raw.githubusercontent.com/Jin-Aladdin/aladdin-spec/v0.1.0/schemas/<name>.schema.json`.
  The previous identifiers pointed at an HTML page, so they could not be
  dereferenced, and at a moving branch, so they named a different document over
  time. Impact was assessed first: no published release, no tag, no fork, no
  registry and no published pack, so nothing external could reference them. The
  identifier does not resolve until `v0.1.0` is tagged, which is the honest
  state of a draft. Rationale and alternatives: ADR-0006.
* The project is now spelled *Aladdin*. The rename covers prose, schema `$id`
  values, the `specification.name` constant, every identifier namespace and the
  manifest filename, which changed from `aladin-pack.yml` to
  `aladdin-pack.yml`. The GitHub repository moved to
  `Jin-Aladdin/aladdin-spec`. The change was made deliberately while no
  artifact had been published and no external implementation existed.

=== Added

* `decisions/ADR-0006-schema-identifier-strategy.adoc`: the identifier
  strategy, its impact assessment and the rejected alternatives, including why
  no project domain is invented.
* `scripts/net_guard.py`: three-stage target screening with address pinning
  against DNS rebinding, covering IPv4 and IPv6.
* The `json-api` source adapter: HTTPS-only retrieval with manual redirect
  screening, media type verification, streaming size limits, separate connect
  and read timeouts, conditional requests, retry classification and rate-limit
  recognition.
* `scripts/json_mapping.py`: declarative JSON Pointer mapping with type,
  format and constraint checks, iterative depth limiting, and templates that
  cannot reach attributes or format specifications.
* Update policy support for `mapping`, `transformation`,
  `conditional_requests`, per-source `retry`, separate connect and read
  timeouts and a JSON depth limit, with a rule requiring a json-api source to
  declare all of them over an https URL.
* A real demonstration source in `examples/automated-pack`: the GitHub
  Releases API for `curl/curl`, with source, evidence, claim and entity.
* `.github/workflows/integration-json-api.yml`: the only workflow that reaches
  the real network, dispatchable and weekly, requiring no secrets.
* `tests/test_schema_identity.py`, `tests/test_net_guard.py`,
  `tests/test_json_api_adapter.py`, `tests/test_json_mapping.py` and
  `tests/test_json_api_pipeline.py`.
* `decisions/ADR-0005-autonomous-knowledge-maintenance.adoc`: fifteen binding
  rules for autonomous maintenance and succession, five automation levels,
  three risk classes and a fail-closed pipeline.
* `specifications/automation-v1.adoc`: the first automation specification,
  covering repository layout, the source adapter contract, gates, automation
  state, the audit trail, versioning, workflow contracts and conformance.
* `schemas/entity.schema.json`, `relation.schema.json`, `concept.schema.json`,
  `conflict.schema.json`, `translation.schema.json`, `evaluation.schema.json`,
  `policy.schema.json` and `artifact.schema.json`, completing the canonical
  object series of ADR-0002.
* `schemas/update-policy.schema.json`: the machine-checkable automation policy.
* `scripts/validate.py`: reference validator for schemas, manifests, records,
  cross references and update policies.
* `scripts/check_docs.py` and `scripts/security_scan.py`: documentation and
  security gates.
* `scripts/source_adapters.py` and `scripts/update_engine.py`: the
  deterministic update engine with a fixed adapter registry.
* `scripts/build_artifact.py`: reproducible artifact builder with provenance.
* `scripts/automation_health.py`: heartbeat and staleness reporting.
* `examples/automated-pack`: a working example of the automation layer.
* `templates/knowledge-pack-repository`: the controlled starting point for a
  new Knowledge Pack repository, with inert defaults.
* `CONTRIBUTING.adoc`, `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `SECURITY.adoc`
  and `SUCCESSION.adoc`.
* Workflows for validation, release, automation health and manual recovery.

=== Changed

* Every workflow, in this repository and in the template, now declares a
  per-job runtime ceiling and pins every action to a commit SHA. Previously no
  job bounded its runtime and every action was referenced by a mutable tag, so
  an upstream tag move could silently change what runs with repository
  permissions.
* Adapter dispatch is by declared name rather than function identity, so the
  registry stays the single source of truth.
* The minimal example pack now demonstrates the full graph: source, evidence,
  claim, two entities, a concept and a typed relation.
* Path safety and path presence are separate checks in the validator. A source
  file that vanished is a retrieval failure the engine records and retries, not
  an invalid policy.
* The artifact builder no longer claims reproducibility without a source
  commit, because that claim is not verifiable without one.

=== Fixed

* Change detection over a whole response body reported a change on every run
  for the real demonstration source, because the endpoint returns reaction
  counts that move while the release does not. At `propose` level that would
  have opened a pull request on every scheduled run. A `mapped-values` method
  was added, which hashes only the declared extracted values; the body hash is
  still recorded as provenance. Found by running the pipeline against the live
  endpoint three times and observing three candidates where there should have
  been none.
* A rate-limited run was reported as no-change, because the branch that ends a
  run without a candidate only recognized outright failure.
* The offline update tests began contacting the live API once the example pack
  gained a network source. They now disable non-static sources explicitly, so
  no unit test depends on an external endpoint.
* `examples/minimal-pack/aladdin-pack.yml` had lost its YAML indentation and
  could not be parsed, which made the manifest impossible to validate.
* ADR-0003 and ADR-0004 had lost their AsciiDoc listing and quote delimiters,
  so literal blocks rendered as prose and an embedded YAML example lost its
  indentation.
* The example claim referenced a concept that did not exist in the pack.
* The project status table claimed that the manifest schema, the validator and
  the example pack had not been started.
