This directory contains the smallest practical example of an Aladdin Knowledge Pack.

== Purpose

The example demonstrates:

* a valid `aladdin-pack.yml` manifest
* one source record
* one precise evidence record
* one source-backed claim
* two canonical entities
* one concept that classifies them
* one typed relation connecting the entities
* declarative content only
* relative entry-point paths
* explicit language and license metadata
* an experimental lifecycle state

== Collections

[cols="1,1,2",options="header"]
|===
| Directory
| Identifier namespace
| Content

| `claims/`
| `claim:`
| Knowledge statements. The example claim is a definition with status `source-backed`.

| `sources/`
| `source:`
| Origins referenced by claims, evidence and entities. The example source is this repository's README.

| `evidence/`
| `evidence:`
| Precise locations inside a source. The example evidence points at one README section.

| `entities/`
| `entity:`
| Stable objects that claims and relations can reference. The examples are the Knowledge Pack itself and the specification that defines it.

| `concepts/`
| `concept:`
| Classification handles for retrieval and grouping. The example concept is the Knowledge Pack category.

| `relations/`
| `relation:`
| Typed connections between entities, concepts and claims. The example relation records that the Knowledge Pack is defined by the specification.
|===

Every file uses JSON Lines: exactly one JSON object per line.

== Reference Graph

[source,text]
----
source:aladdin.spec.readme
        │
        │ located in
        ▼
evidence:aladdin.spec.readme.knowledge-pack-definition.001
        │
        │ supports
        ▼
claim:aladdin.knowledge-pack.artifact.001
        │
        │ is about
        ▼
entity:aladdin.knowledge-pack ──── defined-by ────► entity:aladdin.specification
        │
        │ classified as
        ▼
concept:knowledge-pack
----

Sources and evidence are kept separate on purpose. A source identifies an
origin, while evidence identifies the exact part of that origin used for a
claim.

Entities and concepts are separate for a similar reason. An entity denotes one
specific object; a concept denotes a category of meaning that several entities
can belong to.

== Validation

The pack is validated by the reference validator in this repository:

[source,text]
----
python scripts/validate.py --pack examples/minimal-pack
----

The validator checks the manifest against `schemas/manifest.schema.json`,
every record against its collection schema, identifier uniqueness, entry-point
existence and every cross reference between records.

== Important

This example targets the draft `0.1.0` specification. No stable `1.0.0`
specification has been released, so the structure may still change.

The pack is declarative data only. Nothing in this directory is intended to be
executed by a consuming runtime.
